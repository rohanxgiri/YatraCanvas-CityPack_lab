# YatraCanvas CityPack Lab

YatraCanvas CityPack Lab is the desktop-first quality, curation, and release workstation for City Packs generated by [YatraCanvas DataFactory](https://github.com/rohanxgiri/YatraCanvas-DataFactory).

It lets contributors inspect a pack, correct places and images, complete manual QA, evaluate data quality and travel readiness, and build a certified artifact for the YatraCanvas traveller application. The bundled source `yatracanvas.db` is always treated as immutable; human work is stored separately as Git-trackable curation records.

## Who should use it

- **Contributors** use Fix Center, Places, Images, and Review Queue to improve a city.
- **Reviewers** complete the required stratified manual QA sample and verify corrections.
- **Release managers** inspect hard blockers, create release evidence, and run certification.
- **DataFactory maintainers** receive durable curation that is reapplied during later provider rebuilds.

This is not the traveller application and it does not fetch remote POI enrichment. It evaluates only the data and media bundled in the local pack.

## Safety rules

1. Source SQLite packs are read-only. Certification modifies a staged copy.
2. Verified human values take precedence over automated provider values.
3. Additions and exclusions survive DataFactory rebuilds.
4. Zero manual reviews means `NOT STARTED`, never passing.
5. Fewer than 50 required reviews blocks release.
6. Critical failures override average quality scores.
7. Production publication requires explicit `READY` evidence.
8. Missing attribution, invalid paths, orphaned curation, or checksum failures stop publication.

## Prerequisites

- Flutter stable compatible with the repository's `pubspec.yaml`
- Python 3.12 or newer for the complete three-repository workflow
- Chrome for web review, or Windows desktop for the full local-filesystem workflow
- Sibling checkouts for production publication:

```text
Documents/
├── YatraCanvas-DataFactory/
├── YatraCanvas-CityPack-Lab/
└── YatraCanvas/
```

Desktop is recommended for curation, local image import, Git-tracked files, and publication. Web mode is useful for review but has browser storage limitations.

## First-time setup

From the CityPack Lab repository:

```powershell
flutter pub get
.\citylab.ps1 setup
```

List available DataFactory packs and copy one into the lab:

```powershell
python tools/sync_city_packs.py --list
python tools/sync_city_packs.py --cities "Jaipur"
```

The synchronized input appears under:

```text
assets/city_packs/<city_id>/
├── yatracanvas.db
├── manifest.json
├── image_manifest.json
├── images/
└── curation/
```

## Contributor workflow

1. **Select a city pack.** Confirm the city, version, database integrity, and pack metadata.
2. **Review Home.** Read Data Quality, Travel Readiness, manual QA progress, and current blockers independently.
3. **Use Fix Center.** Work through missing photos, opening hours, coordinate problems, category problems, and open issues.
4. **Use Places.** Search the inventory, edit supported fields, add missing places, or exclude invalid places with a reason.
5. **Import images.** Supply the source page, author, licence, licence URL, contributor, and valid image file. The lab generates `primary.webp` and `thumbnail.webp`.
6. **Complete Review Queue.** Finish the configured 50-place stratified sample. A partial sample remains an active release blocker.
7. **Inspect Release Gate.** Resolve every critical blocker. High numerical scores cannot override a failed hard gate.
8. **Export release evidence.** From Release Gate, save the generated `release_<city_id>.json`. This file records the city, source pack version, gate status, scores, and manual QA result.
9. **Run certification.** Use the evidence file with the command below. Certification validates curation, SQLite integrity, media, attribution, counts, manifests, and checksums.
10. **Publish explicitly.** Add `--publish` only after reviewing the local result and only when the sibling repositories are the intended production targets.

Human changes are written under `assets/city_packs/<city_id>/curation/` as entity-level JSON. They do not mutate the source database.

## Build a certified artifact

Production certification requires a new output directory and explicit Release Gate evidence:

```powershell
python tools/export_certified_pack.py `
  --city jaipur `
  --release-evidence "C:\path\to\release_jaipur.json" `
  --output-dir "releases\jaipur\2026-09-28"
```

A successful artifact contains:

```text
release.json
manifest.json
image_manifest.json
checksums.json
yatracanvas.db
images/<place_id>/primary.webp
images/<place_id>/thumbnail.webp
```

The source database remains unchanged. The output manifest and checksums are generated from the final staged database and copied media.

## Publish to DataFactory and YatraCanvas

Publication is never implicit. Run certification with `--publish` and a previously unused output directory:

```powershell
python tools/export_certified_pack.py `
  --city jaipur `
  --release-evidence "C:\path\to\release_jaipur.json" `
  --output-dir "releases\jaipur\2026-09-28-certified" `
  --publish
```

On success, publication:

- copies the portable curation bundle to `YatraCanvas-DataFactory/data/curated/<city_id>/`;
- includes referenced curated image bytes with that bundle;
- copies the certified artifact to `YatraCanvas/assets/city_packs/<city_id>/`;
- uses staged directory swaps and rollback if a target update fails.

DataFactory reapplies that curation after provider image processing and before scoring and validation. Verified human fields are restored after scoring, preventing automated refreshes from silently replacing them.

The PowerShell helper exposes the same explicit controls:

```powershell
.\citylab.ps1 export `
  -City jaipur `
  -ReleaseEvidence "C:\path\to\release_jaipur.json" `
  -OutputDir "releases\jaipur\2026-09-28-certified" `
  -Publish
```

## Developer-only export

To inspect a local artifact without `READY` evidence:

```powershell
python tools/export_certified_pack.py `
  --city jaipur `
  --output-dir "scratch\jaipur-dev" `
  --force-dev-export
```

This bypasses only release eligibility. Curation, database, path, and media validation still run. The result is marked `non_certified` and cannot be published.

## What certification failures mean

Certification is fail-closed. A failure prints numbered blockers, exits non-zero, removes staging output, and does not update production targets.

Common blockers:

- release status is `BLOCKED` or `REVIEW_REQUIRED`;
- release evidence belongs to a different city or pack version;
- manual QA is incomplete;
- a curation record references an unknown place ID;
- an override is not verified;
- a curated image is missing source, author, licence, contributor, dimensions, or hash metadata;
- an image path escapes the pack or references a missing file;
- SQLite integrity or a generated checksum does not match.

Do not fill missing provenance with guesses. Correct the curation record using a verifiable source and retry with a new output directory.

## Repository architecture

```text
YatraCanvas DataFactory
        │ generates provider-derived pack
        │ reapplies durable human curation
        ▼
YatraCanvas CityPack Lab
        │ quality + travel readiness
        │ curation + reviews + release gate
        │ fail-closed certification
        ▼
Certified City Pack
        │
        ▼
YatraCanvas traveller application
```

Reusable business rules and repository contracts are kept separate from Flutter screens, local paths, Git layout, and sibling-repository publication. This is the migration boundary for a future authenticated `YatraCanvas → AdminShell → City Data` module; the standalone lab remains the workstation for now.

## Current limitations

- Release Gate produces evidence, but its screen does not yet launch the Python certification command.
- Production publication expects the three repositories to be sibling checkouts.
- Cross-repository publication uses staging and rollback but cannot be one operating-system transaction.
- `city_packs_index.json` generation and traveller-side certified-pack discovery are deferred.
- Exact canonical place IDs are the only automatic reconciliation key; uncertain identity changes require human review.
