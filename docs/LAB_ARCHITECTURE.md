# YatraCanvas CityPack Lab Architecture

## System Overview

YatraCanvas CityPack Lab is an independent, mobile-first QA testing application built with Flutter, designed to validate real traveller product flows against production City Pack datasets generated by `YatraCanvas-DataFactory`.

```
┌────────────────────────────────────────────────────────┐

└──────────────────────────┬─────────────────────────────┘
                           │ tools/sync_city_packs.py
                           ▼
┌────────────────────────────────────────────────────────┐
│            YatraCanvas-CityPack-Lab (Assets)           │
```

## Key Architectural Principles

### 1. Zero Production Mutation & Immutability
- The shipped database `yatracanvas.db` in `assets/city_packs/` is never modified.
- SHA256 hashes are recorded upon synchronization in `lab_sync_receipt.json`.
- At runtime, the database is opened via `openReadOnlyDatabase` to ensure zero write locks or schema modifications.
- QA annotations, problem reports, test trip baskets, and scenario ratings are persisted in a separate location: `ApplicationDocuments/qa_sessions/qa_<city>.json`.

### 2. Strict Offline Isolation & Zero Network Leaks
- The application makes **zero network requests** for POI enrichment, geolocation, or place details.
- All places originate strictly from the SQLite database.
- Missing images always render a dedicated **"No local image"** placeholder.
- In **Strict Offline Data Mode**, even OpenStreetMap background tiles are disabled, rendering a coordinate canvas instead to permit inspection without any external internet traffic.

### 3. Local Search Engine
- Search does not use remote APIs or fuzzy external engines.
- Queries execute deterministic SQL queries matching against `name`, `name_hi`, `category`, `subcategory`, `primary_entity_type`, `address`, and tags in `place_tags`.
- Queries order results by `tourism_priority DESC, travel_relevance_score DESC`.
- Paged via `LIMIT` and `OFFSET` to ensure sub-50ms queries even on large 10,000-record datasets (e.g., Jaipur).

### 4. Deterministic Random Sampling
- Review Mode uses a pseudo-random number generator seeded with a reproducible integer (`seed = 42`).
- This allows testers to review identical samples across multiple runs or share sample sets with colleagues for cross-validation.
