# City Lab Curation Rebuild Audit

**Document**: `docs/CITY_LAB_CURATION_REBUILD_AUDIT.md`  
**Date**: September 27, 2026  
**Project**: YatraCanvas City Pack Lab → YatraCanvas City Pack Curation Studio  
**Target City Packs Audited**: Jaipur (10,060 places), Gulmarg, Manali, Panaji, Rishikesh  

---

## 1. Executive Summary

This audit establishes the concrete state of `YatraCanvas-CityPack-Lab` prior to its transformation into the **YatraCanvas City Pack Curation Studio**. The audit inspects real code, database schemas, test results, and runtime flows to identify why the current tool functions as an isolated, technical QA viewer rather than an actionable, collaborative curation environment.

## 3. Current Problems & Root-Cause Findings

### 3.1. Zero Curation Capability (Data can be viewed, but NEVER corrected)
- **Problem**: In `PlaceDetailScreen`, `ReviewScreen`, and `DataCoverageScreen`, a user can inspect places, see missing photos, or view missing opening hours. But there are **no editors** for:
  - Opening hours
  - Coordinates (no interactive pin-drag or bounds validator)
  - Categories (cannot reclassify a place)
  - Images (cannot replace, upload, or supply URLs)
  - Names, descriptions, or contact information
  - Adding completely missing places
  - Excluding inappropriate places
- **Impact**: QA testers identify issues, write a note in a dialog, but the data never improves.

### 3.2. Local Storage Trapping & Non-Persistent Curation
- **Problem**: When QA reviews or issues are logged, they are saved into `AppDocuments/qa_sessions/qa_<cityId>.json` on the individual tester's machine.
- **Impact**:
  - Changes are **not in git**, cannot be shared with colleagues, and cannot be committed via Pull Request.
  - If the database is regenerated by `YatraCanvas-DataFactory`, any local manual state is disconnected or lost.
  - There is zero entity-level curation storage (`overrides/`, `additions/`, `exclusions/`).

### 3.3. Confusing Navigation & Overly Technical UI
- **Problem**:
  - The UI presents 5 dense tabs (`Overview`, `Coverage`, `Review`, `Release Gate`, `Diagnostics`) plus 3 extra AppBar actions (`Search`, `Discover`, `Map`).
  - There are orphaned or duplicated screens: `qa_dashboard_screen.dart`, `random_review_screen.dart`, `scenario_testing_screen.dart`, `test_trip_screen.dart`, `expected_places_screen.dart`.
  - Non-technical contributors are confronted with SQL statistics, candidate pipeline rejection counts, quartile formulas, and JSON manifest internals.
  - The Home screen lacks a clear 10-second scan answering: *What is the city health? What needs fixing? What is my next task?*

### 3.4. Missing Fix Center & Task Orientation
- **Problem**:
  - The application tells the user: "Opening hours coverage = 1.2% (63 Core places lack hours)".
  - Clicking this in `DataCoverageScreen` opens a raw list of places, but there is no structured "Fix Center" where a contributor can work through issues step-by-step with a "Save & Next" flow.

### 3.5. Review Queue State Loss & Repetition
- **Problem**: In `ReviewScreen`, when `all` (stratified 50 sample) is selected, `_loadPlaces()` calls `qaSamplingService.generateSample(repo.database)` without cross-referencing already-reviewed place IDs from `qa_session.dart`.
- **Impact**: The user reviews a place, approves it, leaves the tab, returns, and is presented with the exact same place at index 0.

### 3.6. Categorization Mismatch in `ReleaseGateService`
- **Problem**: In `lib/quality/services/release_gate_service.dart`, Gate 5 ("Itinerary Sights Minimum") checks:
  ```dart
  final culturalSightCount = (categoryCounts['attraction'] as int? ?? 0) +
      (categoryCounts['monument'] as int? ?? 0) +
      (categoryCounts['temple'] as int? ?? 0) +
      (categoryCounts['museum'] as int? ?? 0) +
      (categoryCounts['viewpoint'] as int? ?? 0) +
      (categoryCounts['park'] as int? ?? 0);
  ```
  In the real SQLite database and `manifest.json`, the taxonomy stores sights as `heritage` (208 places in Jaipur), `religious` (163 places in Jaipur), `nature` (23 places in Jaipur), `arts_culture` (68 places in Jaipur). Neither `attraction` nor `monument` nor `temple` exist as primary categories.
- **Impact**: The gate was passing only because `park` (119) and `museum` (40) exceeded 10, while completely ignoring 371 heritage and religious monuments.

### 3.7. Static / Fake Values in Overview Screen
- **Problem**: In `OverviewScreen`:
  ```dart
  final readyCount = totalPlaces - outsideBounds - sharedCoords;
  final reviewCount = outsideBounds + sharedCoords;
  final excludedCount = 0; // Hardcoded
  ```
  This is a heuristic placeholder rather than an accurate count of curated, ready, and excluded places.

### 3.8. Web/WASM Compatibility Smell
- **Problem**: `lib/data/local_place_repository.dart` imports `dart:io` unconditionally at line 1, even though it does not use it. Under web compilers, unconditional `dart:io` imports can trigger build errors.

### 3.9. No Multi-Contributor Git Collaboration Strategy
- **Problem**:
  - No scripts exist for simple one-command setup or startup (`scripts/setup-city-lab.ps1`, `scripts/start-city-lab.ps1`).
  - No deterministic serialization exists for human changes.
  - No branch or PR guide exists for external data curators.

## 5. Scope of Implementation

1. **Curation Storage System**:
   - Deterministic entity-level JSON files in `assets/city_packs/<city>/curation/` (`overrides/`, `additions/`, `exclusions/`, `reviews/`, `issues/`).
   - Reversible human overrides with explicit provenance and field resolution rules.
2. **Curated Place Resolution & Quality Recalculation**:
   - `CuratedPlace = Generated Place + Human Overrides + Manual Additions - Manual Exclusions`.
   - Quality score and release gates immediately reflect manual fixes.
3. **Simplified UI (Contributor vs Admin Mode)**:
   - Primary navigation: `Home`, `Fix`, `Review`, `Places`, `Release`, `Advanced`.
   - Dedicated Fix Center with Opening Hours Editor, Coordinate Editor, Image Curator, Category Editor, Place Details Editor.
   - 5-step "+ Add Place" wizard and Place Exclusion flow.
   - Clean, visual Home screen with 10-second city health scan and primary CTA.
4. **Git Collaboration & Setup Scripts**:
   - `scripts/setup-city-lab.ps1` and `scripts/start-city-lab.ps1`.
   - `docs/CITY_LAB_CONTRIBUTOR_GUIDE.md` and `docs/CITY_LAB_CURATION_ARCHITECTURE.md`.
   - Curation change summary generator for Pull Requests.
5. **Bug Fixes**:
   - Unconditional `dart:io` imports resolved.
   - Real category taxonomy wired into `ReleaseGateService`.
   - Review queue deduplication against already reviewed places.
   - Heuristic counters replaced with real curated aggregates.
